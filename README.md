# CSS Box Model — Content-Box vs Border-Box

ვიზუალური საგანმანათლებლო პრეზენტაცია დამწყები დეველოპერებისთვის, რომელიც თვალსაჩინოდ აჩვენებს, როგორ ითვლის ბრაუზერი ელემენტის ზომებს CSS Box Model-ში.
პროექტი შესრულებულია მხოლოდ **სუფთა HTML**-ითა და **CSS**-ით.

## რას შეიცავს გვერდი

1. **შესავალი (Hero)** — სათაური და მოკლე შესავალი, რატომ არის Box Model ვებდეველოპმენტის საფუძველი.
2. **Box Model-ის 4 შრე** — Content, Padding, Border და Margin ჩადგმული ფერადი ბლოკებით (DevTools-ის მსგავსად) და განმარტებებით.
3. **დიდი დუელი: Content-Box vs Border-Box** — ორი ბარათი ერთნაირი `width: 300px`, `padding: 20px`, `border: 5px solid` პარამეტრებით:
   - ბარათი A (`content-box`) → რეალური სიგანე **350px**
   - ბარათი B (`border-box`) → რეალური სიგანე **300px**
4. **რატომ ტყდება განლაგება?** — ორი 50%-იანი სვეტი `padding: 20px` და `border: 2px solid`-ით:
   - `content-box` → მეორე სვეტი ქვემოთ ვარდება (Broken Layout)
   - `border-box` → ორივე სვეტი მშვიდად ეტევა ერთ ხაზზე
5. **ოქროს წესი (Best Practice):**

```css
   *, *::before, *::after {
     box-sizing: border-box;
   }
```

## დამატებითი ფუნქციები

- `:hover` ეფექტები ბარათებზე (`transform: translateY(-5px)` და `box-shadow`)
- თანამედროვე ფერთა პალიტრა CSS ცვლადებით (`:root`)
- Responsive დიზაინი მობილურისთვის
- ინგლისური, სემანტიკური კლასების სახელები (BEM სტილში: `.card--content-box`, `.column--border-box` და ა.შ.)


## თვითშემოწმება

**რა ემართება ელემენტის გარე ზომას `content-box`-ის დროს, როდესაც padding-ს ვზრდით?**
გარე ზომა იზრდება, რადგან padding და border ემატება მითითებულ `width`-ს.

**რა ემართება კონტენტის ადგილს `border-box`-ის დროს, როდესაც padding-ს ვზრდით?**
ელემენტის გარე ზომა უცვლელი რჩება, ამიტომ კონტენტისთვის დარჩენილი ადგილი მცირდება.

**რატომ ითვლება `border-box` თანამედროვე ვებდეველოპმენტის ოქროს სტანდარტად?**
ზომები პროგნოზირებადია: რაც `width`-ად დაწერე, ზუსტად იმდენს დაიკავებს ელემენტი. ხელით გადათვლა აღარ გჭირდება და პროცენტული განლაგებები არ ტყდება.
